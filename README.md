# 音声課題の提出ツール（voice-submit）

学生がスマホでリンクを開き、画面の語や文を発音して録音し、聞き直してから送信する。
録音は先生の Google ドライブに WAV（16bit・モノラル・端末の標準サンプリング周波数）で保存され、提出記録はスプレッドシートに残る。

- `index.html` … 学生が開く画面（GitHub Pages などに置く）
- `config.js` … 受付先URL（空欄だとデモモード：録音はできるが送信しない）
- `gas/Code.gs` … 受付側（Google Apps Script）

## 仕組み

1. 学生が `https://<公開先>/?a=<課題ID>` を開く
2. 学籍番号・氏名を入れ、マイクを許可
3. 1項目ずつ録音 → 波形と再生で確認 → 録り直し可
4. 全項目の一覧で聞き直し → 「この内容で提出する」
5. 項目ごとに送信（途中で切れたら、送れていない項目だけ送り直す）→ 受付番号を表示

録音時はエコー除去・ノイズ抑制・自動音量調整を切っている（音声分析に使えるよう、加工しない音を取る）。
音割れ・音が小さすぎる・短すぎる録音には、その場で録り直しを促す表示が出る。

## 設置手順（初回だけ）

1. Google ドライブで新しいスプレッドシートを作る（名前は例えば「音声課題_受付」）
2. 「拡張機能」→「Apps Script」を開き、`gas/Code.gs` の中身を貼り付けて保存
3. 関数 `setup` を選んで「実行」→ 権限を許可する
   - シート「課題」「受信ファイル」「提出一覧」と、ドライブにフォルダ「音声課題_提出」ができる
4. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
   - 表示された URL（`https://script.google.com/macros/s/…/exec`）を控える
5. `config.js` の `apiUrl` にその URL を入れ、`index.html` と `config.js` を公開先に置く

大学の Google Workspace で「全員」を選べない場合は、学生がログインなしで送れないので、個人の Google アカウントで作る。

`Code.gs` を直したときは「デプロイを管理」→ 既存のデプロイを編集 →「新しいバージョン」にする（URL が変わらない）。

## 課題の作り方

シート「課題」に1行1項目で書く。課題名・説明・締切は、その課題IDの最初の行だけ書けばよい。

| 課題ID | 課題名 | 説明 | 締切 | 項目番号 | 提示文 | 読み・補足 | 最長秒数 |
|---|---|---|---|---|---|---|---|
| eng01 | 第1回 母音 | ふだんの速さで1回ずつ | 2026/10/20 23:59 | 1 | heed | /hiːd/ | 10 |
| eng01 | | | | 2 | hid | /hɪd/ | 10 |

学生に送るリンク：`https://<公開先>/?a=eng01`

- LINE で送るときは末尾に `&openExternalBrowser=1` を付けると、LINE の中ではなく Safari / Chrome で開く（LINE 内ブラウザはマイクが使えないことがある）
- 締切を過ぎると、画面でも受付側でも提出できなくなる。締切が空欄なら無期限

## 届いたものの見方

- 録音：ドライブ `音声課題_提出/<課題ID>/<学籍番号>_<氏名>/<課題ID>_<学籍番号>_<項目番号>_<日時>.wav`
- 「提出一覧」：1回の提出につき1行（受付番号・受信数・状態）。「不足あり」は途中で通信が切れたもの
- 「受信ファイル」：録音1件につき1行（秒数・サンプリング周波数・ピーク値・ファイルへのリンク）
- 再提出は新しい提出として別ファイルで残る（上書きしない）

## 注意

- 学生の声は個人情報。ドライブのフォルダを他人と共有しない
- 受付URLを知っていれば誰でも送れる（課題IDの照合と締切・サイズの確認だけしている）
- 動作確認：iPhone は Safari、Android は Chrome。アプリ内ブラウザ（LINE・Instagram 等）では警告を出す
